Contract constraints (for test-plan writing — not beta execution)

A1–A2 · Schema v1

develop → schema_contract.json
  • Every Pro Postgres table/column name, type, and nullability is fixed in JSON.
  • JSON columns must match schemas in contracts/payloads/*.json.
  • BE CI fails if models drift from the file (tests/test_schema_contract.py).

B1 · OpenAPI (API)

develop → api.md openapi.json not on develop yet
  • Defines future /api/v1/pro/* and admin routes, request headers, and error codes.
  • UI must not compute metrics — only display API fields (plan cases from api.md).
  • No Pro HTTP API to run on beta until routes ship (Week 2+).

C1 · Pipeline (Dagster Pro sync)

develop → contract_constants.py
  • DB role: pro_pipeline · Dagster tag pipeline=pro.
  • Cycle states (on pro_refresh_cycle): open, ready, reported, incomplete, failed.
  • crawl_result.result_type (pipeline): prompt_answer, product_call, chip_answer (PDP read from Databricks, not crawl_result).
  • Tables pipeline may write: pro_refresh_cycle, crawl_* targets, crawl_result, snapshot tables, asin_cycle_result, pro_sync_watermark, topic, tracked_prompt, asin_slot (after activation rules).
  • Queue tables: pipeline may only set applied_cycle_id on prompt_edit_queue / asin_swap_queue.
  • Insert-only audit: pro_admin_action.
  • Pipeline must not write: pro_account, pro_user_action, queues (except column above), pro_schema_version.
  • Timing: INCOMPLETE_GRACE_HOURS = 48 after cycle end for late crawls.
  • Must stay aligned with A1–A2 schema; CI: neoiq-data-platform/tests/dagster_code/pro/test_contract_constants.py.

Summary: Week 1 run on beta = W1-01, W1-02, W1-03 (health only). Contracts above = planning docs + develop links, not Week 1 test execution.
